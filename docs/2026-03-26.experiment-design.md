## RAG Architecture

### Embedding

- **Model:** `gemini-embedding-001` (3072 dimensions)
- **Vector store:** Vertex AI Vector Search (only)
- **Query time:** strip Python comments → embed full source → vector search

### Ingest Strategy

| Collection | Text embedded into Vertex AI | Why |
|---|---|---|
| `grammar_mappings` | `python_pattern` only | Query is Python source → match on Python side |
| `parallel_corpus` | Python code side only | Same — find similar Python code |
| `api_mappings` | `python_api` only | Same — match Python API usage |
| `go_docs` | `{description} Example: {example}` (Go text) | Queried with Go API names (see pipeline below), not Python source |

### Query Pipeline (per translation request)

```
1. strip_python_comments(source)           → stripped_source

2. [if A] grammar_mappings.query(stripped_source, k)
          → go_pattern + description per match

3. [if B] parallel_corpus.query(stripped_source, k)
          → python_code + go_code per match

4. [if C] api_mappings.query(stripped_source, k)
          → python_api + go_api + description per match
          → collect go_api names → go_api_query

5. [if C and D] go_docs.query(go_api_query, k)
          → api + description + example per match

6. Format all results → inject into LLM prompt
```

Step 4 → 5 is the bridge: Go API names from api_mappings are used as the query for go_docs. This means go_docs is only ever queried with Go terminology, which is what it is indexed on.

No tree-sitter grammar extraction at query time. `grammar_extractor.py` is no longer used in the retrieval path.

## Parallel Experiment Runner

### Overview

A single `run-all` command that launches all 5 experiments simultaneously — one process per experiment, each using threads internally for LLM calls. Two modes: `smoke` (10 files, validate pipeline) and `full` (all 164 HumanEval-X files). One LLM model per invocation.

### Architecture

```
run-all command
    │
    ├── Process 1: baseline             → N threads → LLM API calls
    ├── Process 2: rag-pattern-only     → N threads → LLM API calls
    ├── Process 3: rag-pattern-samples  → N threads → LLM API calls
    ├── Process 4: rag-pattern-api-docs → N threads → LLM API calls
    └── Process 5: rag-full             → N threads → LLM API calls
```

Each process:
- Enables the model in its own registry state
- Loads HumanEval-X dataset independently
- Uses `ThreadPoolExecutor` with `batch_size` workers for LLM calls
- Writes translated files to the normal output paths
- Writes progress/results to a per-experiment log file

Main process:
- Spawns all 5 processes, waits for all to finish
- Shows a live Rich status table (experiment → status: running/done/failed)
- Prints a final summary table with Compilation@1 and Pass@1 per experiment when all done

### Smoke vs Full

| Mode  | `sample`      | Purpose                            |
|-------|---------------|------------------------------------|
| smoke | 10            | Validate full pipeline end-to-end  |
| full  | None (164)    | Final experiment run               |

Implementation: use `multiprocessing.Queue` for (experiment, files_done) updates, or `Process.is_alive()` polling (simpler, no shared state).

### API Rate Limit

MiniMax M2.5 official limits:
- Normal hours: **~50 TPS**
- Off-peak hours: **~100 TPS**

With 5 processes running concurrently, the combined request rate across all processes must stay within these limits. Budget per process:

| Time        | Total TPS | Per-process budget (5 processes) |
|-------------|-----------|----------------------------------|
| Normal      | 50        | ~10 req/s per process            |
| Off-peak    | 100       | ~20 req/s per process            |

**Throttling strategy:** use a shared `multiprocessing.Semaphore` or a global token-bucket (via `multiprocessing.Queue`) that all 5 processes acquire before each LLM call. Default cap: 40 req/s total (80% of normal limit, safety margin). Expose as `--rate-limit` CLI option (default `40`).

On HTTP 429 (rate limit exceeded), back off with exponential retry (1 s → 2 s → 4 s, max 3 retries) before failing the file.

**Practical implication:** for `full` mode (164 files × 5 experiments = 820 requests), at 40 req/s the minimum wall-clock time is ~21 s of pure API time; actual runtime will be longer due to prompt/response sizes.

### Key Constraints

- Subprocess function must be top-level (picklable) — no lambda or nested function
- Each process calls `enable_model()` independently (module-level state is not shared across processes)
- Preflight runs once in the main process before spawning, not repeated per subprocess (`skip_preflight=True` in subprocesses)
- Vertex AI RAG retriever is initialized lazily inside each subprocess — no shared connections
- Total concurrent LLM request rate must not exceed 50 TPS (normal) / 100 TPS (off-peak); use shared rate limiter across all 5 processes
